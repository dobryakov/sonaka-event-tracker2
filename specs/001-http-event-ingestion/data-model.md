# Модель данных: события (HTTP-приёмка)

## Сущность: Event (событие)

Логическая модель соответствует спеку FR-002, FR-009, FR-010 и разделу Key Entities.

| Поле (логическое) | Тип в API (JSON) | Тип в PostgreSQL | Ограничения |
|-------------------|------------------|------------------|-------------|
| `id` | выдаётся только в ответе | `BIGSERIAL` PRIMARY KEY | генерируется БД |
| `system_name` | string | `TEXT` NOT NULL | обязательно в запросе |
| `object_id` | string | `TEXT` NOT NULL | обязательно в запросе |
| `event_name` | string | `TEXT` NOT NULL | обязательно в запросе |
| `metadata` | object или array | `JSONB` NOT NULL | обязательно; допустимы вложенные структуры JSON |
| `event_time` | string (RFC 3339 / ISO 8601) | `TIMESTAMPTZ` NOT NULL | в запросе обязательно как строка; семантика хранения по FR-002 и допущениям спека |

### Правила валидации (согласовано со спеком)

1. **Обязательные поля запроса**: `system_name`, `object_id`, `event_name`, `event_time`, `metadata`. Отсутствие любого — отказ приёмки (4xx) с машиночитаемой ошибкой.
2. **`metadata`**: MUST быть JSON-объектом `{}` или JSON-массивом `[]` на верхнем уровне поля (не скаляр, не `null`). Иное — отказ.
3. **`event_time`**: если строка успешно разбирается как момент времени — в БД сохраняется этот момент (нормализация к UTC на уровне типа `TIMESTAMPTZ`). Если разбор невозможен — сохраняется время приёма запроса на сервере (UTC); ответ при этом остаётся успешным при прочей валидности.
4. **Повторные доставки**: каждая успешная приёмка создаёт новую строку (нет дедупликации в объёме фичи).

### Индексы (минимум на первую итерацию)

- Первичный ключ по `id` — достаточен для сценария автотеста «выборка по id».
- Дополнительные индексы (по `event_time`, `system_name`) не требуются спеком для MVP; внести в отдельную задачу при появлении запросов на выборки.

### Состояния и переходы

Сущность не имеет жизненного цикла: запись создаётся один раз и не изменяется в объёме фичи.

### Миграции

Одна миграция «создание таблицы событий» (имя таблицы, например `events`) с перечисленными столбцами; при необходимости — расширение комментариями к столбцам для операторов.
